# Cursed Guild MVP Build Guide for Claude Code

## Project Summary

Build a 2D Steam-style strategy/management MVP called **Cursed Guild**.

The player runs a cursed fantasy guild. Each day, they manage a roster of strange guild members, choose contracts from a contract board, equip relics, upgrade rooms, and send teams on dangerous expeditions. Expeditions resolve through a lightweight simulation, not real-time combat.

The game should use static 2D art, UI panels, icons, portraits, cards, and simple visual effects. Do not build a large world, action combat, multiplayer, procedural animation, or online systems for MVP.

The core goal is to create a polished vertical slice that proves the loop is fun:

**Review guild → choose contract → assign team/relics → resolve expedition → gain rewards → upgrade guild → repeat.**

---

# 1. Recommended Tech Stack

Use **Unity 2D with C#**.

Target platform: **PC / Steam-style desktop build**.

Resolution target: **1920x1080**, scalable UI.

Use:

* Unity UI Toolkit or Canvas UI. Canvas is acceptable for speed.
* ScriptableObjects or JSON for game data.
* Static PNG sprites.
* No 3D.
* No multiplayer.
* No live AI generation inside the game.

The game should be data-driven so new characters, relics, rooms, and contracts can be added without rewriting code.

# 3. Core Gameplay Loop

## Main Loop

1. Player starts in the Guild Hub.
2. Player sees:

   * current resources
   * current day/week
   * roster
   * contract board
   * rooms
   * equipped relics
3. Player selects a contract.
4. Player assigns 1–3 guild members.
5. Player optionally equips relics.
6. Player clicks **Embark**.
7. Expedition resolves automatically.
8. Game shows:

   * success/failure
   * injuries
   * rewards
   * new relics/materials
   * reputation changes
9. Time advances.
10. Player spends rewards on:

* recruiting
* crafting
* room upgrades
* healing/resting

11. Repeat.

# 8. Party Assignment

For MVP, each expedition allows:

* Minimum party size: 1
* Maximum party size: 3
* Equipped relic slots: 0–3

The party’s total stats are calculated by summing member stats, then applying relic and room modifiers.

Example:

```text
Party Might = sum(member.might) + relic bonuses + room bonuses
Party Magic = sum(member.magic) + relic bonuses + room bonuses
```

A contract has stat challenges. The party succeeds based on comparison between party stats and challenge requirements.

---

# 9. Expedition Resolution

Do not build real-time combat for MVP.

Use an auto-resolution system.

## Resolution Steps

1. Calculate party total stats.
2. Apply relic bonuses.
3. Apply room bonuses.
4. Apply contract difficulty modifier.
5. Roll random variance.
6. Determine outcome:

   * Great Success
   * Success
   * Partial Success
   * Failure
   * Disaster

## Suggested Formula

```text
partyPower = weighted sum of relevant stats
contractPower = sum of contract stat challenges
successChance = 50 + ((partyPower - contractPower) * 5)
clamp successChance between 5 and 95
```

Example:

```csharp
successChance = Mathf.Clamp(50 + ((partyPower - contractPower) * 5), 5, 95);
```

## Outcome Thresholds

Roll 1–100.

```text
roll <= successChance - 25 = Great Success
roll <= successChance = Success
roll <= successChance + 15 = Partial Success
roll <= successChance + 35 = Failure
otherwise = Disaster
```

## Outcome Effects

### Great Success

* full rewards
* bonus XP
* possible relic
* no injury

### Success

* full rewards
* normal XP
* minor injury chance

### Partial Success

* 50–70% rewards
* injury chance
* possible curse

### Failure

* low rewards
* injury
* morale loss

### Disaster

* no rewards
* heavy injury
* possible member unavailable for several days
* reputation loss

# 19. Asset Pipeline

The generated art uses neon pink background #FF00FF.

Claude Code should create or support an import utility that can:

1. Load PNG sprite sheets.
2. Replace pixels close to #FF00FF with transparent alpha.
3. Slice sheets into sprites based on grid settings.
4. Assign sprites by ID manually or through metadata.

For MVP, manual assignment is acceptable. Automated slicing is a bonus.

## Important

Do not rely on AI-generated text inside images. All names, descriptions, numbers, buttons, and UI text should be rendered by the game engine.

# 25. Expedition Preview Formula

Calculate:

```text
contractChallenge = relevant stat challenge total
partyPower = party stat total + relic bonuses + room bonuses + trait bonuses
baseChance = 50 + ((partyPower - contractChallenge) * 5)
difficultyModifier:
  Easy: +10
  Medium: 0
  Hard: -10
moodModifier: average mood modifier
riskModifier: trait-based bonuses/penalties
finalChance = clamp(baseChance + difficultyModifier + moodModifier + riskModifier, 5, 95)
```

Show final chance as:

* Safe: 75–95%
* Risky: 50–74%
* Dangerous: 25–49%
* Suicidal: 5–24%

Start by building the playable loop using ugly placeholder rectangles and text.

Do not spend time perfecting art import until the logic works.

Implementation order:

1. Data models
2. Game state
3. UI shell
4. Contract selection
5. Party assignment
6. Success chance calculation
7. Expedition resolution
8. Rewards
9. Room upgrades
10. Relics
11. Save/load
